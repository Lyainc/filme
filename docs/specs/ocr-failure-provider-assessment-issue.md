## 증상

2026-09-19 사용자가 현재 OCR이 제대로 동작하지 않는다고 신고했어요. 기대 동작은 티켓 이미지에서 정보를 인식해 편집기에 채우는 것이에요. 사용자는 Google AI Pro 구독을 중단한 사실을 알렸고, 이것이 원인이라면 다른 LLM provider로 이전하는 방안을 별도 작업으로 추적해 달라고 요청했어요. 로컬에서는 요청 제한용 Upstash 주소의 DNS 실패가 확인됐고, provider 이전 필요성은 확인되지 않았어요.

## 재현

2026-09-19 사용자 요청으로 512×580 JPEG 합성 이미지(TEST MOVIE / TEST CINEMA / 2099-01-01 / 12:00 / A1, QR·예매번호 없음)를 `{image: base64, mimeType: 'image/jpeg'}`로 `/api/ocr`에 POST했어요. 기존 로컬 개발 서버, 별도 로컬 빌드 서버, 배포 사이트 모두 HTTP 500으로 재현됐어요. 기존 로컬과 배포의 GET은 정상적으로 405를 반환했어요. 사용자가 처음 실패했던 이미지와 화면 오류 문구는 여전히 미확인이에요.

## 원인 (선택)

별도 로컬 빌드에서는 요청 제한용 Upstash Redis 연결의 `FailedToOpenSocket`이 발생했고, 해당 호스트는 로컬 및 공용 DNS 1.1.1.1·8.8.8.8에서 `ENOTFOUND`로 실패했어요. `validateOcrRequest`의 요청 제한 검사가 Gemini 호출보다 앞에 있으므로 로컬에서는 모델 호출 전 실패예요. 배포의 HTTP 500도 같은 원인인지는 함수 로그를 확인해야 해요. Vercel CLI의 인증 토큰이 유효하지 않아 배포 로그 조회는 실패했어요. 현재 라우트는 API 키로 Gemini를 직접 호출하며 Google 공식 문서는 AI Pro 웹 혜택과 외부 앱 API 과금을 구분해요. 구독 해지와의 인과관계, Gemini 키·과금·잔액 상태는 확인하지 않았고 provider 이전이 필요하다는 근거도 아직 없어요.

## 실측 (선택)

수정 전 앱 OCR POST는 3회예요. 기존 로컬 개발 서버는 500·4.744초·HTML 오류, 배포 사이트는 500·6.636초·Internal Server Error, 별도 로컬 빌드는 500·4.339초·Internal Server Error였어요. 앱 요청 수를 Gemini 모델 호출 수로 취급하지 않아요. 실제 티켓 업로드는 자동 승인 검토에서 거절돼 실행하지 않았고, 허용된 합성 이미지로만 검사했어요. 인식 정확도는 측정하지 못했어요.

## 확인한 것

로컬 코드에서 요청 제한 저장소의 연결 예외가 처리되지 않은 채 OCR 라우트로 전파되는 경로를 확인했어요. 이는 정상적인 한도 초과(429)나 설정 미지정(503), API 키 누락, 모델 호출 실패와 구분해야 해요. 열린 12건·닫힌 400건의 이슈를 용어 기반으로 좁혀 본 결과 #773이 관련 후보로 나왔고, 본문에서 자동 재시도와 장애 안내 구분을 다룬 완료 이슈임을 확인했어요. 이번 이슈는 그 처리를 다시 구현하자는 요청이 아니며 실제 실패 환경에 #773의 수정이 반영됐는지도 구분해야 해요. 로컬 코드를 배포 코드와 같다고 가정하지 않아요. 실제 키 값과 원문 서버 로그는 이슈에 싣지 않아요.

## 로컬 수정 및 검증

사용자 요청으로 공통 limiter의 생성·통신 예외 및 SDK timeout을 처리했어요. OCR/공유는 JSON 503으로 차단해 과금 보호를 유지하고 KOBIS는 기존 fail-open 정책을 유지해요. main 407393e의 #773 수정과 테스트도 현재 작업본에 반영해 실패와 정상 빈 결과를 구분했어요. 변경은 로컬 미커밋 상태이며 배포·환경 설정은 변경하지 않았어요.

같은 합성 이미지로 수정한 로컬 빌드를 재검사한 결과 500 대신 503 application/json, {"error":"Rate limit is unavailable"}, 4.325초였어요. 전체 테스트 1,313개와 타입 검사·린트·빌드가 통과했어요. 이 결과는 장애 처리 개선의 근거이며 OCR 200 복구의 근거는 아니에요. 유효한 Upstash 연결 설정 복구와 배포 원인 확인이 남아 있어요.

## 왜 지금 걸렸나 (선택)

모바일 UI 디자인 명세 인터뷰 중 사용자가 현재 OCR 실패와 AI Pro 구독 중단 사실을 함께 알렸어요. 장애 시작 시점과 구독 해지의 선후 관계는 확인되지 않았어요.

## 방향 (선택)

먼저 배포 함수 로그와 Upstash 연결 대상·서비스 상태를 확인하고 로컬 DNS 실패 원인을 해결해요. 요청 제한 저장소 장애를 제어된 오류로 안내하되 비용 보호를 우회해서는 안 돼요. 복구 후 OCR 200과 실제 필드 인식을 재검증하고, 그때도 provider 문제가 확인될 경우에만 이미지 입력·구조화 출력·한국어 인식·비용·제한을 기준으로 대안을 비교해요. provider를 변경한다면 기존 티켓 정답 데이터로 정확도를 비교하고 필드 스키마, 적용·되돌리기, 실패 시 초안 보존을 검증해야 해요. 원인 근거, 유지 또는 이전 판단, 정상 OCR 및 실패 안내 확인 결과가 남으면 완료로 봐요. 디자인 리디자인과 별도 작업으로 진행하며 모델·프롬프트·SDK·rate-limit 수치는 근거 없이 교체하지 않아요.
