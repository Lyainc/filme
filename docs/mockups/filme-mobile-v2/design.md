# FILME 모바일 편집 목업

2026-09-24. 기존 v2 경로에서 계속 개선하는 모바일 목업이에요. 단일 편집 화면, 주황 계열 브랜드 색 `#B0423F`, Pretendard, 라이트 UI를 유지해요. PC에서도 같은 모바일 화면을 제공하며 전용 데스크톱 레이아웃은 없어요. **프로덕션 적용 전 검토용 HTML 목업**이에요.

## 화면과 상호작용

- **랜딩:** 중앙 브랜드, 5장 티켓 캐러셀, 작은 만들기 CTA를 하나의 중앙 그룹으로 배치해요. 캐치문구는 제거해요. 캐러셀은 감상용이며 탭·스와이프·길게 누르기에 반응하지 않아요. 10초 간격 자동 전환만 유지하고 동작 줄이기 설정에서는 정지해요. 시작 버튼은 기본 Minimal로 열고, 여섯 디자인은 편집기에서 선택해요.
- **편집 헤더:** 돌아가기 · 정보 채우기 · 메뉴 · 완료. 로고와 즉시 공유 버튼을 두지 않아요. OCR·영화 검색은 상단 가져오기 안의 두 방식으로 통합해요.
- **캔버스 조작:** 티켓 바로 아래에 실행 취소 · 전체 미리보기 · 다시 실행을 한 줄로 모아요.
- **편집 도구:** 정보·사진·디자인·색상·질감·로고가 기본 252px 패널을 사용하고, 색상은 212px·고정 색상 디자인은 136px로 내용에 맞춰 줄여요. 패널과 하단 도구를 하나의 연결된 표면으로 묶어요. 패널 상단에 16px 안쪽 여백을 확보해 조작부가 테두리에 붙지 않게 해요. 메뉴 이름을 본문에 반복하지 않으며 접근성 제목만 남겨요. 사진도 별도 모달 대신 이 패널에서 선택·제거·불투명도·배치를 조절해요. 실제 자르기만 모달로 열어요.
- **정보 입력:** 영화·관람·기록 그룹 아래 관련 native 필드를 함께 배치해요. 항목별 탭과 이전/다음 화살표는 제거하고, 필요한 항목을 바로 누르거나 Enter로 이동해요. 한글 조합 중 Enter는 가로채지 않아요. 입력된 값의 출처는 라벨 옆에, 표시·숨김·서체·날짜 설정은 필드별 설정에 모아요. 빈 제목에만 필수 입력 단서를 표시해요.
- **편집 대상:** 현재 필드·사진·로고 위치를 티켓 바깥의 미리보기 오버레이로 표시해요. 자연 픽셀 티켓 DOM에 테두리를 추가하지 않아요. 편집 도구가 열려 있을 때에는 중앙 사진 추가 CTA를 숨기고 사진 도구 진입은 유지해요.
- **사진·로고:** 사진이 없으면 사진 선택과 샘플을 제공하고, 등록 후 교체·자르기·제거·배치·불투명도를 보여줘요. 사진 배치는 전체 보기/영역 채우기로 표시해요. 로고는 현재 텍스트/이미지 상태를 명시하고 해당 조작부를 제공해요.
- **디자인·질감·색상:** 같은 문서로 여섯 무드 썸네일을 비교해요. 화살표는 목록만 스크롤하고 썸네일을 눌러 선택해요. 소재·코팅 견본은 선택을 돕는 근사 표현이며 실제 결과는 티켓에서 확인해요. 브랜드색 표시명은 브릭, 기존 저장 값 오렌지는 호환해요. 색 프리셋과 불투명도는 구분해요.
- **키보드:** 헤더와 도구를 접고 수정 중인 실제 티켓 조판 부분을 확대해 보여줘요. 키보드 위에는 190px 입력 패널을 유지해요. 작은 높이에서는 내부 스크롤을 허용해 입력 오류와 설정이 잘리지 않게 해요.
- **모달:** 일반 대화상자는 화면의 상하좌우에서 최소 12px 떨어진 중앙 카드예요. 제목 영역은 72px이고 제목·닫기·첫 조작부에 별도의 안쪽 여백을 둬요. VisualViewport 변화에 맞춰 높이와 중심을 조정하며 내용이 길면 안쪽만 스크롤해요. 전체 화면 미리보기는 기존 전체 화면 방식을 유지해요.
- **정렬과 밀도:** 메뉴·설정·입력·긴 설명은 좌측 정렬하고 수치·스위치·화살표는 우측에 배치해요. 짧은 확인창·분류 탭·색상 견본은 중앙 정렬을 유지해요. 색상 패널은 빈 헤더를 예약하지 않고 실제 적용 대상 라벨을 닫기 옆에 둬요.
- **완성 확인:** 완료를 누르면 같은 화면에서 편집 도구를 접고 결과·저장 및 공유·다시 편집을 보여줘요. 제목과 숫자 검증, 문서 변경 후 이전 완료 승인 무효화는 유지해요.
- **모바일 화면 경계:** 500px 이상에서는 430px 앱 영역 밖을 별도 중성색으로 구분해요.
- **서비스 메뉴:** 아이콘 옆에 이름, 우측에 상태/화살표를 배치해요. 자동 저장은 스위치로 즉시 변경해요. 브랜드와 목업 안내·이전 목업 링크는 하단의 접을 수 있는 안내에 모아요.
- **자동 저장:** 끄면 이후 저장만 중단하고 기존 저장본은 보존해요. 꺼진 동안 변경은 재진입 시 복원되지 않으며 설정 행에서 이를 알려줘요. 다시 켜면 현재 문서를 저장해요.
- 새 티켓과 꾸미기 초기화는 확인 후 적용해요. 새 티켓 확인에는 사진·입력·꾸미기의 초기화 범위를 명시해요. 새 티켓은 이전 문서의 실행 취소 기록을 지우고, 같은 티켓의 꾸미기 초기화는 되돌릴 수 있어요.

## 데이터 출처

필드 단위로 `OCR`, `OCR · 수정`, `영화 검색`, `영화 검색 · 수정`, `직접 입력`, `샘플`을 표시해요. OCR이 채우지 않은 항목은 기존 값과 출처를 보존해요. 출처가 없던 구버전 임시 저장은 추정하지 않고 `출처 미상`으로 표시해요. 하단 입력 패널에만 표시하며 완성 티켓의 인쇄 요소에는 추가하지 않아요.

## 구현과 검증 경계

- 기존 `Mood*.tsx` 여섯 컴포넌트를 재사용해요. 티켓의 자연 픽셀 크기 960×1534 / 1534×960은 유지해요. 목업 소스와 에셋만 변경하며 제품 렌더러·API·JPEG 출력 코드는 수정하지 않아요.
- 입력은 native date/time/number를 사용해요. 잘못된 숫자는 사용자 입력을 보존하고 오류를 표시해요. 터치 환경에서 시트를 열 때는 키보드를 자동으로 열지 않아요. 티켓을 직접 눌러 편집할 때만 입력에 포커스를 둬요.
- VisualViewport 높이·위치 변화에 맞춰 시트와 하단 입력 패널이 움직여요. 실제 iPhone 키보드 검증은 Chrome 모사 테스트와 구분해요.
- 사진과 로고는 JPG·PNG·WebP 5MB 이하를 기기 안에서 처리해요. 크롭 결과는 투명 PNG를 유지하고 긴 변을 최대 1600px로 줄여 임시 저장 부담을 제한해요. 저장 공간을 초과하면 경고해요.
- **검색·OCR·파일 저장·OS 공유는 샘플 동작**이에요. 관련 시트에 샘플 표시를 하고 메뉴에서 범위를 명시해요. 실제 외부 API를 호출하지 않아요.
- 현재 검증은 `verify-experience.mjs`, `verify-redesign.mjs`, `verify-mobile.mjs`, `verify-refinement.mjs`가 담당해요. 기존 report/live-report와 이전 PNG는 이전 개선 단계의 증거이며 최신 검증으로 간주하지 않아요.

## 레퍼런스 적용의 범위

Apple Photos·Google Photos의 작업물 중심 편집, Snapseed의 속성별 조절, Canva·Adobe Express의 같은 문서 안에서의 콘텐츠 편집, Instagram의 미리보기와 프리셋 접근, Pinterest의 이미지·메타데이터·게시 구분을 참고했어요. 구체적 FILME 배치 결정은 이를 응용한 설계이며 앱의 실제 화면을 그대로 재현한 것이 아니에요. 모든 컨트롤을 떠 있는 버튼으로 만드는 시각 스타일은 채택하지 않아요. 모달을 없앤 정보 패널과 키보드 위의 티켓 부분 확대는 이 제품의 작은 인쇄 조판을 입력 중에도 확인하기 위한 설계예요.

레퍼런스의 공식 자료는 위 표에 연결돼 있어요. Apple HIG 일부 페이지는 현재 도구에서 JavaScript 안내만 반환하므로, 세부 배치의 확인 근거로 과장하지 않아요. 확인 가능한 Apple Photos 사용 설명과 실제 제품 코드의 캐러셀 동작을 우선 사용했어요.

### 추가 조사에서 선택한 기준

Lightroom의 한 작업물 중심 구성, VSCO의 결과를 보며 선택·강도를 조절하는 흐름, Etsy의 이미지 편집과 최종 잘림 확인이 가장 직접적인 참고예요. 전자는 상단 가져오기·캔버스 조작·하단 조정의 역할 구분에, 나머지는 사진 인라인 편집과 옵션/슬라이더의 가까운 배치에 적용했어요. VSCO의 재탭으로 강도를 여는 방식은 기능을 숨기므로 적용하지 않고 강도를 계속 노출해요. Medium·Spotify·Notion은 보조 비교 사례이며 게시 워크플로·SNS·커버 제작 기능을 추가하지 않아요.

중앙 플로팅 모달은 유지하되, 그 안의 정렬은 기능별로 구분해요. 일괄 중앙 정렬은 최신 사용자 피드백에 따라 폐기했어요. 위 앱들이 모두 같은 모달 배치를 쓴다는 의미가 아니에요. 조사 자료가 설명하는 기능·순서와 실제 화면의 시각 배치는 구분해요.

## 임시 Seed 대조표 (v7 반영)

명세는 처음 임시 파일로 저장했으며, 브랜치 분리 시 `docs/mockups/filme-mobile-v2/seed.yaml`에 spec_version 2를 보존했어요. v6의 기존 게이트 결과는 이력으로 보존하고, 이번 r11–r16 수정은 별도 1회 검토에서 구현 가능으로 판정했어요. 백로그 조회는 실패했으며, 미구현 원격 이슈와의 충돌 여부는 미확인이에요.

| 요구사항 | 구현 위치/검토 대상 |
| --- | --- |
| r1 공통 패널 | 기본 252px, 색상 212px/고정색 136px·16px 상단 여백·분류 세그먼트·라벨/값 슬라이더 |

| r5 동일 문서 디자인 | DesignPresets, 스크롤과 선택 분리 |
| r6 색상 역할 | 브릭 표시명·사용자 지정 피커·불투명도 구분 |
| r7 질감 견본 | texture-presets와 독립 강도 |
| r8 로고 상태 | 텍스트 입력 / 이미지 편집 진입, 기존 기능 유지 |

| r10 출처·설정 | 값이 있는 필드만 출처 표시, 필드별 표시 설정 |
| r11 메뉴 위계 | 좌측 아이콘/이름·우측 상태, 하단 브랜드와 접을 수 있는 목업 안내 |

디자인 썸네일은 디자인 도구가 열렸을 때만 렌더링해요. 프리셋의 이름·선택 상태는 접근성 속성으로 제공해요. 기능 테스트의 성공은 실제 사용성 평가나 실기기 확인을 대신하지 않아요.

최종 대조와 결함 수정 결과는 [Seed 최종 점검](./verification/seed-audit.md)에 기록했어요. r1–r16의 추가 구현 누락은 발견되지 않았고, Chrome 검증 40개가 통과했어요. 키보드 정책은 `resizes-visual`로 통일했고, 상영 시간은 유효한 입력 원문을 유지하면서 티켓 표시만 숫자로 정규화해요. 실제 기기와 사용자 사용성 평가의 미검증 경계는 점검 문서에 구분했어요.
