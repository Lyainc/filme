# FILME mobile v1

> **2026-09-22 v1 목업의 설계 기록이에요.** 아래 “현재 구조”·“새 구조”·“확정 명세”는 당시 비교와 결정을 가리켜요. 후속 설계는 [v2](../filme-mobile-v2/design.md)에 있으며 이 본문을 현재 프로덕션 변경 지시로 적용하지 않아요.

확정 명세: [filme-mobile-redesign-mockup.yaml](../../specs/filme-mobile-redesign-mockup.yaml).

## 설계 기준

시각적 완성도 → 쉬운 시작 → 직관적인 편집 순서로 검토해요. 첫 완성 80%, 자유로운 꾸미기 20%의 비중이에요. 사용자 확정 강조색은 `#B0423F`예요. 밝은 중립 배경과 Pretendard, 일관된 12–20px 모서리를 사용해요. 티켓은 기존 이미지 그대로예요.

장르는 modern-minimal, 구조는 모바일 제작 흐름이에요. 시작에는 완성 예시와 단일 주 액션, 정보에는 읽기 쉬운 폼, 꾸미기에는 큰 미리보기와 명시적인 옵션, 결과에는 저장 액션을 둬요. 앱의 상단은 뒤로 가기와 현재 위치, 하단은 다음 행동에 사용해요. 목적지가 아닌 제작 단계를 영구 탭 바처럼 표현하지 않아요.

## 기존 화면에서 바꾸는 점

| 현재 구조 | 새 구조 | 이유 |
|---|---|---|
| 좌측 아이콘, 우측 항목 손잡이, 하단 도구로 나뉜 편집 진입 | 정보 폼과 꾸미기 화면, 라벨 있는 옵션 행 | 무엇을 눌러야 하는지 읽고 판단할 수 있어요. |
| 작은 티켓 글자를 직접 눌러 입력 | 일반 폼에서 입력하고 큰 미리보기로 확인 | 키보드와 티켓 위치를 함께 조작할 필요를 줄여요. |
| 입력 패널이 티켓 대부분을 덮음 | 정보 입력과 꾸미기의 작업 공간을 분리 | 각 화면에서 필요한 대상에 집중해요. |
| 비슷한 무게의 도구와 선택지 | 화면별 주 액션 하나, 세부 설정은 하단 시트 | 필수 작업과 선택 작업의 위계를 나눠요. |
| 완료를 눌러야 알 수 있는 필수 값 | 제목·개봉연도를 처음부터 표시하고 필드 옆 오류 | 저장 직전 되돌아가는 상황을 줄여요. |

## 기능 배치

| 기능 | 목업 위치 / 시연 수준 |
|---|---|
| 직접 입력, 영화 검색, OCR | 영화 정보 / 입력과 샘플 성공·빈 결과·오류 |
| 관람일시·극장·좌석 등 | 정보 화면의 관람 기록 펼치기 |
| 포스터와 크롭 | 꾸미기 → 포스터 / 샘플 선택과 크롭 선택 UI |
| 6종 무드 | 꾸미기 상단 디자인 선택 / 기존 이미지 교체 |
| 컬러, 재질, 코팅, 투명도, 크기, 스탬프 | 꾸미기 → 세부 꾸미기 / 선택 상태와 값 조작 |
| 로고, 서명, 한줄평, 서체 | 세부 꾸미기의 로고·문구 그룹 |
| 표시 여부 | 정보 화면의 추가 항목 설정 |
| 실행 취소·다시 실행 | 꾸미기 상단 / 디자인 설정 변경 이력 |
| 초안 이어하기 | 시작 화면 / 별도 목업 저장 키 |
| 저장·공유 | 완료 화면 / 처리·완료·실패 상태만 시뮬레이션 |

미리보기는 고정된 기존 티켓 이미지예요. 입력·포스터·꾸미기 값은 UI 상태를 검토하기 위한 값이며 실제 출력 이미지에는 합성하지 않아요. 디자인 선택만 해당 무드 샘플로 바뀌어요. 이 경계는 목업 안내와 저장 시연에서 밝혀요.

## 토큰과 조작 규칙

- `tokens.css`가 폰트·색·간격·모서리·그림자의 기준이에요. 화면마다 다른 테마를 만들지 않아요.
- 새 조작은 최소 44px 터치 영역, 입력 글자는 16px, 보이는 라벨과 포커스 표시를 사용해요.
- 필요한 문구와 중요 상태는 텍스트로 설명해요. 색이나 아이콘만으로 구별하지 않아요.
- 하단 시트는 초점을 가두고 Escape로 닫혀요. 닫은 뒤 실행한 버튼으로 초점이 돌아가요.
- 이동은 입력을 보존해요. 새 티켓 시작은 기존 초안이 있으면 확인해요.
- 시스템 모션 감소 설정을 따르고, 자동으로 움직이는 랜딩 콘텐츠는 사용하지 않아요.
- 모바일 웹의 실제 브라우저와 키보드를 사용해요. 가짜 상태 바·홈 인디케이터·폰 테두리를 그리지 않아요.
- iOS에서는 화면 순서·명칭·정보 묶음을 이어갈 수 있지만 React DOM 컴포넌트를 네이티브 코드로 옮기는 작업은 별도예요.
