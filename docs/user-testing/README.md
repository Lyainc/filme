# FILME 사용자 테스트 묶음

앱의 주요 사용자 흐름과 [#768](https://github.com/Lyainc/filme/issues/768) Stub 스탬프를 한 캠페인에서 확인하는 실행서예요. 자동 테스트를 대체하지 않으며, **아래 수동 케이스는 아직 실행하지 않았어요.** 2026-09-17 결정에 따라 실기기 검증은 구현 PR의 진행 조건에서 분리하고 이 묶음으로 이관해요. 실기기 호환 통과를 뜻하지 않아요.

## 준비와 판정

1. 테스트할 URL과 커밋 SHA를 고정하고 [결과표](./RUN.md)를 캠페인별로 복사해요. 로컬은 `bun install --frozen-lockfile`, `bun run build`, `bun run start --port 3038` 순서예요. 이미 같은 SHA의 서버가 있으면 재사용해요.
2. 기존 작업을 잃지 않도록 **테스트 전용 브라우저 프로필**에서 시작해요. 실제 예매번호·개인정보 대신 아래 가상 데이터를 써요. 앱 초기화는 이 프로필의 테스트 문서에서만 해요.
3. 저장해 사용할 이미지: [포스터 A](../../public/assets/posters/sample-bus.jpg), [교체 이미지 B](../../public/assets/posters/sample-crossing.jpg). 실행 URL의 `/assets/posters/sample-bus.jpg`와 `/assets/posters/sample-crossing.jpg`에서도 받을 수 있어요. B는 스탬프 입력으로도 재사용해요. 별도 로고나 유료 에셋이 필요하지 않아요.
4. 같은 SHA를 데스크톱 Chrome, 실제 iPhone Safari, 실제 Android Chrome에서 각각 실행해요. 기기가 없으면 해당 실행은 `UNRUN`으로 남겨요. 반응형 에뮬레이션은 실기기 결과로 세지 않아요. 모바일은 기본 세로 화면과 가로 회전을 모두 확인해요.
5. 순서: U01–U13 → S01–S16 → N01–N04 → U14(초기화). 서비스 설정이 없는 환경은 N 항목을 `BLOCKED`로 기록하고 나머지는 계속해요. API 키를 결과표에 기록하지 않아요.
6. 각 항목은 `PASS / FAIL / BLOCKED / UNRUN / N/A` 중 하나와 증거를 남겨요. `PASS`에는 실제 관찰/파일이 필요하고 `N/A`에는 사유가 필요해요. 진행 불가·데이터 손실을 발견하면 해당 흐름을 멈추고 재현 순서와 마지막 정상 상태를 기록해요. 다른 독립 케이스는 계속할 수 있어요.

## #768 상세: S01–S16

Stub에서 모든 공통 입력을 채우고 B를 스탬프로 올려요. 메뉴의 **빈 항목 미리보기는 끄고 필드 편집 포커스도 닫아요.** 개봉일 값 자체는 지우지 말고 표시만 꺼야 완료 조건을 유지할 수 있어요.

- Admission off: 좌석, 관람일, 관람 시간, 극장, 상영관을 모두 표시 off.
- Film off: 러닝타임, 평점, 개봉일, 재개봉, 출연을 모두 표시 off.
- on인 그룹은 해당 표시를 켜고 공통 입력을 사용해요. 재개봉은 선택 가능한 경우 켜요.
- 둘 다 on이면 **두 섹션 사이 빈 공간**, 그 외에는 **마지막 빈 공간**이 스탬프 자리예요. 빈 공간의 오른쪽 중앙에 있고 글자와 겹치지 않아야 해요. 고정 y 숫자를 외워 판정하지 않아요.

| 섹션 조합 | 포스터·짧은 입력 | 포스터·긴 입력 | 포스터 없음·짧은 입력 | 포스터 없음·긴 입력 |
|---|---|---|---|---|
| Admission on / Film on | S01 | S02 | S03 | S04 |
| Admission on / Film off | S05 | S06 | S07 | S08 |
| Admission off / Film on | S09 | S10 | S11 | S12 |
| Admission off / Film off | S13 | S14 | S15 | S16 |

각 셀에서 다음을 모두 수행해요:

1. 해당 포스터/텍스트/섹션 상태를 만들고 스탬프가 예상 빈 공간에 있는지 확인해요.
2. 원제 표시 off→on, 짧은 제목→긴 제목→원래 제목으로 바꿔요. 각각 입력을 닫고 반영을 기다려 이전 좌표 잔류·글자 겹침을 확인해요.
3. 스탬프 크기를 1→1.5로 바꾸고 프리뷰 최대화/복원 또는 화면 회전을 해요. 스탬프는 빈 공간 안에 유지돼야 해요. 긴 입력 셀은 최종 1.5, 짧은 입력 셀은 최종 1로 저장해요.
4. 완료 화면 캡처와 **실제로 저장된 JPEG**를 `Sxx-preview` / `Sxx-saved.jpg`로 남겨 나란히 비교해요. 위치·잘림·누락·글자 겹침 중 하나라도 다르면 FAIL이에요. 사진 앱 확대 상태를 동일 배율로 착각하지 않도록 티켓 전체 경계를 맞춰 비교해요.
5. 다시 편집으로 돌아가 다음 셀로 이동해요. 포스터 없는 셀은 새 포스터 없는 문서를 만들어 같은 입력을 사용해도 돼요.

### 개발자용 자동 사전 점검: 기존 Chrome 도구 16회

실기기 수동 S01–S16과 축은 같지만 입력 이미지/문자열은 도구의 합성 fixture예요. `navigator.canShare`를 false로 두므로 네이티브 공유 시트·사진 앱·터치 조작은 검증하지 않아요. 서버가 **검증할 SHA의 빌드**인지 먼저 확인해요. macOS Chrome 기본 경로 외에는 `CHROME_PATH`를 지정해요. 아래 블록을 저장소 루트에서 실행하면 실패한 셀도 기록하고 나머지 셀을 계속 실행해요.

```sh
bash <<'BASH'
set -u
qa_url=http://localhost:3038/
qa_out=$(mktemp -d /tmp/filme-stub-user-test.XXXXXX) || exit 1
failed=0
for sections in both admission film none; do
  case "$sections" in
    both) off='' ;;
    admission) off=runtime,rating,releaseDate,reissue,actors ;;
    film) off=seat,watchDate,watchTime,screen ;;
    none) off=seat,watchDate,watchTime,screen,runtime,rating,releaseDate,reissue,actors ;;
  esac
  for poster in poster posterless; do
    for length in short long; do
      name="$sections-$poster-$length"
      args=(--url "$qa_url" --layout stub --bg --full-fields --stub-check)
      [[ -z "$off" ]] || args+=(--field-off "$off")
      [[ "$poster" != posterless ]] || args+=(--posterless)
      if [[ "$length" == long ]]; then
        args+=(--long-text --capture-scale 0.25 --bg-scale 1.5)
      else
        args+=(--capture-scale 0.6 --bg-scale 1)
      fi
      if bun scripts/capture-export.mjs "${args[@]}" --out "$qa_out/$name.jpg" >"$qa_out/$name.json" 2>"$qa_out/$name.log"; then
        printf 'PASS %s\n' "$name"
      else
        printf 'FAIL %s\n' "$name"
        failed=$((failed + 1))
      fi
    done
  done
done
printf 'Evidence: %s; failed: %s / 16\n' "$qa_out" "$failed"
test "$failed" -eq 0
BASH
```

## 외부 서비스 흐름

테스트용 서비스 설정과 네트워크가 있는 환경에서 실행해요. 실사용 사진·티켓이나 비밀 키는 업로드/첨부하지 않아요. 의도적 실패는 DevTools의 해당 요청 차단 등 테스트 클라이언트에서만 만들고, 서버 설정을 바꾸거나 요청 폭주로 rate limit를 소진하지 않아요.

|---|---|---|
| N01 영화 검색 | ① 영화 제목 검색 ② 결과 하나 선택 ③ 공통 가상 제목으로 검색해 결과 없음 확인 ④ 네트워크 차단 상태에서 검색 후 복구 | 선택한 결과가 필드에 반영돼요. 결과 없음과 통신 실패를 구별해 안내하고, 직접 입력으로 계속 만들 수 있어요. 검색어·시각·선택 결과를 남겨요. 포스터 자동 제공을 기대하지 않아요. |
