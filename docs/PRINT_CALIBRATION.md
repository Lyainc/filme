# 인쇄 캘리브레이션

실물 포토티켓 인쇄가 우리 export를 어떻게 재현하는지 재는 도구와 그 실측 기록.
관련 이슈: #510(최초) · #521(눈금·안전영역) · #591(v3, 파이썬 이관 + 메가박스 실측).

## 왜 필요한가

`downloadTicketAsJpeg`는 콘텐츠 960×1534 바깥에 `EXPORT_MARGIN_PX = 10`을 흰색으로 두르고
pixelRatio 2로 캡처해 1960×3108 JPEG q0.95를 만든다. 이 파일이 극장 키오스크/앱을 거쳐 신용카드
크기(85.6×54mm) 플라스틱에 인쇄되는데, 그 과정에서 **배율·잘림·선 굵기·톤·색이 전부 바뀐다.**
브라우저 프리뷰만 보고는 알 수 없어서, 같은 export 양식으로 계측 도안을 찍어 실물을 재는 것이
유일한 방법이다.

## 쓰는 법

```bash
uv run scripts/make-calibration-sheet.py
# → calibration-v3.jpg  1960×3108 JPEG q95
#   검증 OK — 재단 띠·프레임 깊이(네 변) · 코너 호 반지름 · 여백·크기 일치
```

옵션: `--out <경로>` · `--scale 2`(pixelRatio) · `--quality 95` · `--html <경로>`(디버그용 HTML 저장).

전제 조건 두 가지.

- **Chrome** — `CHROME_PATH` 환경변수로 지정하거나 macOS 기본 경로에 있으면 된다.
- **`.next/`가 한 번은 생성돼 있어야 한다** — JetBrains Mono를 `next/font/google`이 빌드 때
  받아 `.next/static/media/`에 두기 때문이다. 없으면 `bun dev`나 `bun run build`를 한 번 돌린다.
  폰트를 못 찾으면 스크립트는 **조용히 다른 폰트로 대체하지 않고 던진다** — 대체된 도안은 폰트
  격자를 무의미하게 만들고, 그걸 모르고 인쇄하면 한 판을 버린다.

인쇄할 때는 **100% 실제 크기, 페이지 맞춤 끄기.** 다 찍은 뒤 카드를 자로 재고 매크로로 촬영해
Claude에 다시 넣으면 아래 판독표대로 값을 뽑을 수 있다.

### 왜 파이썬 + headless Chrome인가

v1·v2는 Next 페이지(`src/pages/calibration.tsx`)였다. 도안 한 장 뽑으려고 dev 서버를 띄우고
브라우저에서 버튼을 눌러야 했고, 라우트가 프로덕션에 존재해 `notFound` 게이트를 계속 들고
있어야 했다. #591에서 스크립트로 옮기고 페이지는 지웠다.

단 PIL로 직접 그리지는 않는다. 이 도안의 계측기 중 **폰트 격자만 래스터라이저에 의존**하고,
PIL(FreeType)과 Chrome은 힌팅·안티에일리어싱이 달라서 그러면 프로덕트가 실제로 인쇄되는
모습과 어긋난 것을 재게 된다. 파이썬이 HTML을 만들고 Chrome이 찍으면 래스터라이저·레이아웃
엔진이 프로덕트와 같고, 레이아웃도 CSS가 대신한다. export 크기·양식은 `captureToImage`와
동일하게 유지했다.

바코드는 `_shared.tsx`의 Code128 패턴 표와 `buildBarcodeWidths128C`를 그대로 이식했다(별
라이브러리를 쓰지 않는다) — 모듈 폭이 프로덕트와 같아야 X-dim 실측이 성립한다.

산출물은 생성 직후 스스로를 검증한다. JPEG 픽셀에서 크기·여백·네 변 재단 띠 깊이·프레임 깊이·
코너 호 반지름을 되읽어 대조하고, 어긋나면 "이 도안으로 인쇄하지 마세요"를 띄운다. 기하가 밀린
도안은 나머지 실측 전체를 무의미하게 만든다.

## 도안 판독표

| 계측기 | 재는 것 | 읽는 법 |
|---|---|---|
| **재단 띠** (가장자리 0-5-10-15-20px, 적·먹 교대 4겹) | 풀블리드 재단량 C | 남은 겹수 4/3/2/1/0 → C≈0/5/10/15/≥20 |
| **파란 호 3겹** (코너, 44/52/60px) | 카드 코너 반지름 | 종이 가장자리가 어느 호 안/밖/위에 떨어지나 |
| **8px 정밀 눈금** (변 양끝 80px) | 반지름 정밀화 + 비대칭 크롭 | 호가 어디서 시작하는지 눈금으로 읽는다 |
| **적 4px 프레임** (34px 인셋) | 배율 | 배율 = 실측 프레임 중심폭(mm) ÷ 888 |
| **선폭 × 불투명도** (1~4px × 100/50/34/18%) | 무드 구분선 생존 | 34%=Minimal · 18%=Stub/Editorial 셀이 보이나 |
| **폰트 크기 × weight** (KR 10~24px × w400~900) | 텍스트 밀도 하한 | 어느 칸부터 회색으로 읽히나 |
| **SANS vs MONO** (10/12/14px) | 등폭의 소형 손실 (#575) | 같은 크기에서 어느 쪽이 진한가 |
| **그레이스케일 램프** (0~100%, 양 끝 촘촘) | 톤 붕괴 임계값 | 어느 단부터 옆 칸과 구분이 안 되나 |
| **컬러 2행** | 팔레트 생존 | 특히 `#F4EDE0`이 크림으로 남나 흰색이 되나 |
| **바코드 3종** (286/372/489px) | 스캔 임계 X-dim | 스캐너 앱으로 `0123456789`가 디코드되는 최소 폭 |

직선 크롭과 코너 반지름은 **모양으로 구분된다** — 재단 띠가 변을 따라 균일하게 사라지면 직선
크롭이고, 코너에서 곡선으로 휘어 사라지면 카드 코너 반지름이다.

색은 일반 플라스틱 전사 인쇄기 가정의 일반 캘리브레이션까지만 한다. 기기·잉크 상태마다 재현이
갈려 특정 hex를 골라 사전보정하는 건 근거가 못 되므로, 보정 후보 래더는 두지 않고 **프로덕션에서
실제로 쓰는 값이 살아남나만** 본다. WB 3종(white/gray/black)은 사진 화이트밸런스 기준이다 —
종이 대비 채널비로 읽으면 촬영 WB가 상쇄된다.

## 실측 기록

### 메가박스 (비풀블리드, 2026-07-29 인쇄 · IMG_4548)

붉은 accent 프레임 4코너로 호모그래피를 잡아 티켓 좌표계로 환산했다.

| 항목 | 값 |
|---|---|
| 배율 | 1 티켓px = **0.0474mm** (풀블리드 기준의 84.3%) |
| 인쇄된 콘텐츠 | 45.5 × 72.7mm = 카드의 84.3% × 85.0% |
| 안 찍힌 흰 테두리 | 좌 4.35 / 우 4.14 / 하 6.65 / 상 6.23mm(역산) |
| 카드 vs 인쇄물 기울기 | 0.01° |
| 크롭 | **0** — 네 변 최외곽 잉크가 전부 종이에 남았다 |
| 코너 반지름 | **2.94mm** (우하단 호 182점 접선 구속 원 피팅, 잔차 median 0.23px) |

export 파일(980×1554)이 앉은 영역을 카드와 비교하면 가로 46.5/54 = 0.861, 세로 73.7/85.6 = 0.861 —
두 축이 소수점 셋째 자리까지 일치한다.

> **메가박스 인쇄가능영역 = 카드를 중심 기준 86.1%로 축소한 사각형.** 잘라내지 않고 전체를 축소해
> 가운데 앉힌다. 비풀블리드의 리스크는 모서리 소실이 아니라 "전부 작아져 잔글씨가 안 읽힘"이다.

코너 반지름 2.94mm는 ISO/IEC 7810 ID-1 규격 3.18mm보다 **7.5% 타이트**하다. 규격을 그대로 믿으면
안 된다. (좌하단은 2.04mm가 나왔으나 그 코너가 사진 프레임에 걸려 교점을 외삽해야 했고 잔차
p90이 3.39px라 신뢰도가 낮다.)

### 잉크·톤·폰트 (메가박스 기준)

1 티켓px = 0.0474mm = **0.56 프린터 dot @300dpi.** 한 dot을 못 채운다.

| 피처 | 풀잉크 대비 밀도 |
|---|---|
| solid 면 | 100% (Dmax≈1.9 — 검정 자체는 잘 나온다) |
| 1px INK 실선 | **14~32%** |
| 2px accent 선 | **26% + 색 완전 소실** |
| 1px 교대 라인페어 | 교대가 안 나오고 균일한 밝은 회색 |

폰트 최대 잉크밀도(KR):

| 크기/굵기 | 밀도 | | 크기/굵기 | 밀도 |
|---|---|---|---|---|
| 10px/400 | 58.7% | | 16px/300 | 77.7% |
| 12px/400 | 61.3% | | 16px/500 | **87.6%** |
| 14px/400 | 71.0% | | 16px/700 | 88.5% |
| 18px/400 | 75.7% | | 16px/900 | 89.2% |
| 24px/400 | 82.0% | | | |

**weight가 size보다 싸게 밀도를 회복한다** — 16px/500이 24px/400보다 진하다. 레이아웃 예산이
빡빡할 때 쓸 수 있는 카드다.

톤: 0% vs 1·3% 구분 불가, 97~100% 동일 — **양 끝 5%가 붕괴한다.** 미드톤은 잘 재현된다.
색: 잉크 중성이 차갑다(solid 블랙 종이대비 R 0.050 / G 0.148 / B 0.176 = 청록 편향). `#B0423F`는
채도 33%를 잃었다. CMY 계열은 밝고 깨끗하나 순수 RGB는 어둡고 탁하다(G가 G채널 51%까지만).

### CGV 프리미엄 (풀블리드) — 미실측, 예측만

`EXPORT_MARGIN_PX = 10`은 장식용 흰 테두리가 아니라 **재단 여유**다. CGV 공식앱에 이미지를 넣어
인쇄하면 상하좌우가 실제로 조금 잘려 나오는 것을 관찰해 둔 값(#382에서 20 → #449에서 10)인데,
**잘리는 양 자체는 실측된 적이 없다.** 한 변에서 잘리는 파일 px을 C라 하면
`배율 = 54 / (980 - 2C) mm/px`, `콘텐츠 손실/변 = max(0, C - 10) px`.

| C | 배율(mm/px) | 콘텐츠 손실/변 | 결과 |
|---|---|---|---|
| 0 | 0.05510 | 0 | 0.55mm 흰 테두리가 남는다 |
| **10 (현 여백)** | **0.05625** | **0** | 딱 맞음 = #382·#449의 의도 |
| 20 | 0.05745 | 10px | 콘텐츠 잘림 |
| 30 | 0.05870 | 20px | 더 잘림 |

C=10 기준 파생값(메가박스 대비 ×1.187):

| | 메가박스(실측) | 풀블리드 C=10(예측) |
|---|---|---|
| 1 티켓px | 0.56 dot | **0.664 dot** |
| 1 dot / 2 dot 최소 선폭 | 1.79 / 3.57px | **1.51 / 3.01px** |
| 바코드 X-dim (W=286) | 0.123mm | **0.146mm** |
| KR 10 / 12 / 16 / 24px | 1.34 / 1.61 / 2.15 / 3.22pt | 1.60 / 1.91 / 2.55 / 3.83pt |

- **1px 문제는 배율로 안 풀린다** — 0.664 dot도 한 dot 미만이다. 최소 2px, 안전하게 3px은 두 체인
  공통 결론이다.
- **폰트 하한도 거의 안 움직인다** — 스트로크 dot 수로는 풀블리드 12px ≈ 메가박스 14px(밀도 71%),
  풀블리드 10px ≈ 11.9px(약 60%). 18% 커져도 12px는 여전히 회색 글씨다.
- **바코드는 사정권** — Code128 절대 하한 0.19mm를 넘으려면 폭 286 → **372px**(권장 0.25mm는 489px).
- **코너 손실** — C=10이면 카드 외곽이 콘텐츠 edge와 같아져 반지름 2.94mm = 콘텐츠 좌표 52.3px가
  그대로 걸린다. 무드는 라운딩 없이 사각으로 그리므로 이 호가 콘텐츠를 직접 잘라낸다.

| 코너에서 가로 거리 | 잘리는 깊이 |
|---|---|
| 0px | 52.3px |
| 10px | 21.5px |
| 20px | 11.2px |
| 30px | 5.0px |
| 40px | 1.5px |
| 대각선 최심 | **15.3px** |

**네 변에서 24px 이상 인셋된 콘텐츠는 안전하다.** 무드 패딩(Editorial 44/52/36 · Stub 22/56/26 ·
Criterion 84)은 전부 손실 구간 밖이고, 잘리는 것은 풀블리드 포스터와 Stub 홀로그램 밴드처럼
의도적으로 가장자리까지 채운 장식면뿐이다.

## 실측이 끝나면 할 일

CGV 프리미엄 인쇄 → 재촬영으로 C·코너 반지름·구분선·폰트·크림 종이·바코드를 확정한 뒤:

- **`EXPORT_MARGIN_PX`를 실측 C로 조정** — 1순위. C가 25면 매 인쇄마다 15px/변을 헛되게 버리고
  있는 것이고, C가 5면 5px을 낭비하고 있는 것이다.
- 무드 1px 구분선 정책 결정(2px 승격 vs opacity 상향) — 실효 밀도가 곱셈이라 `1px × .45`와
  `2px × .25`가 같은 값이다. 어느 쪽이 프리뷰에서 덜 무거운지는 시안 판단.
- #575(Criterion 등폭 → Pretendard) · #530(배경 기하 패턴 스트로크 하한) · #509(형압 근접톤) ·
  #576(도판 테두리 폭)에 근거 반영.
- 바코드 폭 결정 — 스캔 가능성을 레이아웃 비용과 맞바꿀지.
