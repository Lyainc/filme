# 랜딩 히어로 에셋

랜딩(#612 → #613 → #615)에서 쓰는 이미지 자산 폴더.

## 현재 상태

비어 있다. 전경 무드 6장(`hero-{minimal,editorial,stub,35mm,35mm-wide,criterion}.webp`)과
`og.jpg`는 실사 자산이 필요해 아직 없다(#613).

배경 타일 그리드는 자산이 아니라 라이브 렌더다 — `Landing.tsx`의 `LandingBackdropTiles`가
`MOOD_CHIP_BG` 색면을 회전 타일로 그린다(원본 포스터가 아닌 색면이라 D5 원본 식별 불가를
그 자체로 만족).

**한때 이 폴더에 `backdrop-tiles.webp`(같은 그리드를 `scripts/bake-landing-backdrop.mjs`로 구운
정적 시트)가 있었지만 뺐다** — 구운 시트는 한 테마로 고정되는데(다크로 구웠다) 라이브 렌더는
테마별 대비를 스스로 맞춰서, 연결하면 라이트 테마가 깨진다. 즉 소비할 수 없는 자산이었고,
`LAYOUTS`/`MOOD_CHIP_BG`가 바뀌면 조용히 stale해지는 수동 번들이기까지 했다. 배경을 정적
이미지로 바꿀 이유가 생기면(예: 라이브 24 div의 렌더 비용이 실측으로 문제가 될 때) 테마별로
두 장을 굽는 것부터 다시 설계할 것 — 한 장으로는 안 된다.

## 새 자산을 넣을 때

`#613`의 실사 무드 이미지가 준비되면 여기에 넣고 `Landing.tsx`가 참조한다. 수동 번들이라
자산이 코드(`LAYOUTS`·`MOOD_CHIP_BG`)와 어긋나도 아무도 안 잡아준다는 걸 전제로, 무드를
추가·개편할 때 이 폴더를 같이 볼 것.
